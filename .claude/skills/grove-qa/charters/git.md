# Git: changes, staging, commits, worktrees, checkpoints

Make edits in the demo repo, then work through the Git Changes view: stage and
unstage by file and by hunk, write a commit, push, and look at what the view says
before and after each step. Create a worktree, switch to it, merge it, archive it.
Look at checkpoints.

Watch for: a status that does not refresh, a staged/unstaged count that disagrees
with `git status`, a commit button that is enabled with nothing to commit, a
worktree left behind after archiving, errors shown as nothing at all.
